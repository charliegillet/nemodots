# Tool and execution-path coverage matrix (revision 2)

Every model-visible read and every mutating execution path in the OpenDots server at `ab39f250`, with its classification and the treatment NemoDots applies for **incident agents**: the Nemotron planner/workers, and any OpenDots Dot whose id is listed in `NEMODOTS_INCIDENT_DOT_IDS` (comma-separated; `Dot` has no profile field, `src/shared/types.ts:79-94`, so the list is the mechanism; with the list empty every defence-in-depth row below is **inactive** and upstream behaviour is byte-for-byte unchanged — finding I4). `file:line` references were checked against the tree on 2026-10-17.

Environment change: CopilotKit Intelligence is **available** (LEAD_NOTES, 13:40 PDT). Dot turns run, so sections 2-3 are verified with fixtures **and live** (W3.3 creates one incident Dot through `POST /api/dots`, lists its id in the env, and drives one conversation turn). NemoDots mission control never depends on Intelligence.

Classification: `read` (no state change outside captures/audit), `mutate`, `unknown`. Treatment: `instrumented` (kept enabled; for mission tools a ledger record is written, for OpenDots Dot-turn tools only the policy applies and nothing is recorded as mission evidence, see the scope ruling below), `policy-checked` (executes only after a server-side predicate at its execution boundary), `disabled` (not registered or fails closed for incident agents), `n/a-blocked` (cannot run in this environment; still classified).

Default rule (fails closed): a tool or capability not in this table is **disabled** for incident agents. A name containing `read`, `list` or `get` is not proof of read-only; MCP `readOnlyHint` is a hint (`src/shared/connection-types.ts:7`, `src/server/connections.ts:188`), never proof.

Interception point for R1-R8, R13 (policy and limited receipts, **not** recording of Dot-turn model calls): the `chat()` in `dot-agent.ts` receives `middleware: [provenanceMiddleware(scope)]` only when a sink is installed or the Dot is an incident Dot. `onBeforeToolCall` enforces the registry with `skip` + a visible tool error. `onConfig` builds a ContextSnapshot in memory and gates the offered tools; the snapshot is **discarded** because the composed sink has no `recordSnapshot`. `onAfterToolCall` calls the sink's `registerToolResult` for read tools: for an incident Dot's `read_space_page` that registers the authority-free page receipt, adds it to the turn's vector and remembers it server-side per `(thread, toolCallId)`; for anyone else it returns nothing. `onFinish` would build ModelCallRecords only if the sink attributed the turn (`identify()`), and the composed sink returns null, so **no Dot-turn model call is recorded**; `onUsage` is not used. The tool array is wrapped by `withToolPolicy(tools, scope)`, which wraps **only tools that carry an executor**; client tools (`review_space_page`, `request_connection_action`) are returned untouched for ordinary Dots so interrupts still work (finding I7); for an **incident** Dot a client tool the registry refuses (`request_connection_action`) is given a **refusing executor**, so a call comes back as a visible tool error instead of an interrupt left pending (TP-10), and incident Dots are offered **no connection tools at all** (R10). The turn runs inside an `AsyncLocalStorage` provenance scope so `connection-tools.ts` can bind the turn's dependency vector to an approval (M9/M10) and so the page feed can tell an incident Dot's turn from an owner edit.

**Scope ruling (TP-70/TP-71).** OpenDots Dot chat turns are outside the controlled incident scope. The mission team (coordinator, worker loop, actions) is the controlled scope. A Dot turn has no mission, task or attempt, so the ledger (which fails closed on a model call without a real attempt) records no model call or snapshot for it. What the middleware does for a Dot turn is policy enforcement (`withToolPolicy`, approval revalidation) and instrumentation of the provider host and timing; for incident Dots it also registers page receipts without authority as described in R8/M1. Voice (`voice.ts`) is a separate non-Crusoe provider path (`api.openai.com` realtime with `VOICE_API_KEY`); it is disabled in the incident scope and never uses `OPENAI_API_KEY`.

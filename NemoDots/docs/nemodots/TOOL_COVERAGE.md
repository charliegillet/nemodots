# Tool and execution-path coverage matrix (revision 2)

Every model-visible read and every mutating execution path in the OpenDots server at `ab39f250`, with its classification and the treatment NemoDots applies for **incident agents**: the Nemotron planner/workers, and any OpenDots Dot whose id is listed in `NEMODOTS_INCIDENT_DOT_IDS` (comma-separated; `Dot` has no profile field, `src/shared/types.ts:79-94`, so the list is the mechanism; with the list empty every defence-in-depth row below is **inactive** and upstream behaviour is byte-for-byte unchanged — finding I4). `file:line` references were checked against the tree on 2026-10-17.

Environment change: CopilotKit Intelligence is **available** (LEAD_NOTES, 13:40 PDT). Dot turns run, so sections 2-3 are verified with fixtures **and live** (W3.3 creates one incident Dot through `POST /api/dots`, lists its id in the env, and drives one conversation turn). NemoDots mission control never depends on Intelligence.

Classification: `read` (no state change outside captures/audit), `mutate`, `unknown`. Treatment: `instrumented` (provenance recorded, kept enabled), `policy-checked` (executes only after a server-side predicate at its execution boundary), `disabled` (not registered or fails closed for incident agents), `n/a-blocked` (cannot run in this environment; still classified).

Default rule (fails closed): a tool or capability not in this table is **disabled** for incident agents. A name containing `read`, `list` or `get` is not proof of read-only; MCP `readOnlyHint` is a hint (`src/shared/connection-types.ts:7`, `src/server/connections.ts:188`), never proof.

## 1. NemoDots incident toolset (the only tools the Nemotron team ever sees)

Registered by `src/server/nemodots/team/tools.ts` (wave 4). Identity and permissions come from `context.context = AttemptContext` set by the coordinator. Receipt ids supplied by the model are **citations validated against the attempt's scope** (emitting snapshot vector, readset, inherited vector; CONTRACTS section 5), never authority; mission/task/attempt ids are never accepted from the model.

| Tool                            | Class  | Treatment      | Boundary                                                                                                                                                                                                                                                                   |
| ------------------------------- | ------ | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `observe_source`                | read   | instrumented   | `ledger.registerObservation` in one transaction (sources row `FOR UPDATE`): receipt or confirmation + readset edge + `tool_call.recorded` event; source key validated against the registry; scope from context; normalized per ARCHITECTURE 9.4                            |
| `list_runbooks`, `read_runbook` | read   | instrumented   | static files under `src/server/nemodots/team/runbooks/`; `read_runbook(id)` resolves through the catalogue map only (no path join; traversal ids rejected, finding I13); digested into `runbooks[]`                                                                        |
| `get_task_status`               | read   | instrumented   | coordinator snapshot of a task **in the same mission** only                                                                                                                                                                                                                |
| `wait_for_children`             | read   | instrumented   | moves the task to `waiting`; fenced                                                                                                                                                                                                                                        |
| `publish_finding`               | mutate | policy-checked | fenced publish (G2, `FOR SHARE` on controlled rows) of a `Finding` with `trust: model_claim`; citations scope-checked; cannot create receipts                                                                                                                              |
| `delegate_task`                 | mutate | policy-checked | fenced enqueue; depth/breadth/total caps, capability ⊆ parent ∩ role defaults, cycle check, `justification` required; specialists may delegate `verifier` only                                                                                                             |
| `propose_action`                | mutate | policy-checked | `ActionAdmissionPort.propose`: strict payload per `ActionKind`; dependency vector = emitting model call's `snapshot.dependencyVector` ∪ scope-checked citations (server-computed); `idempotencyKey` from the tool call id; author fence validated; admission/commit per G1 |
| `request_replan`                | mutate | policy-checked | fenced; schedules a `replan` attempt for the planner; bounded to 3 per mission                                                                                                                                                                                             |

No shell, browser, file system, HTTP fetch, SQL or Redis command is exposed to the model. Injector, probe and verifier credentials are process-level and never appear in any tool result.

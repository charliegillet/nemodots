## Cleared hypotheses (passing tests kept as regressions)

Each line names the attack, then the test that defeated it.

- **Look-alike and unregistered tool names.** Names containing `read`/`list`/`get`, case and whitespace variants, a zero-width space, a Cyrillic `е`, MCP-shaped `mail__read_inbox` (readOnlyHint true), Composio names, `computerexec`, `__proto__` and `''` are all `deny_unknown` and refused. `disabled` and `deny_unknown` names are refused even when the predicate says yes (`registry.test.ts` TP-31, TP-31b). The same names emitted in a live-shaped Dot turn execute nothing and contact no host but the provider (`dot-turn.test.ts` TP-04 x9).
- **Registry completeness.** Every registered name has its TOOL_COVERAGE row and treatment, and every `computer_*` action is disabled (TP-30, TP-30b). The incident id list is exact: no prefix, substring or case match (TP-32). With the list empty, executors are returned identical and every policy method passes (TP-33). For incident Dots, `withToolPolicy` refuses synchronously before the executor runs and leaves executor-less tools untouched (TP-34).
- **Page writes.** `edit_space_page` is refused even into the projection Space, with a visible tool error, and the page is unchanged (TP-03). The same edit works for an ordinary Dot, so the harness is real (TP-03b). An explicit non-projection `spaceId` is refused while the projection Space is allowed (TP-02b). With no projection Space configured, every incident create is refused (TP-02c). A channel/headless turn applies the same policy (TP-03c).
- **Learned skills (R5/R13).** With skill delivery configured on the incident Dot, no `copilotkit_*` tool is offered, no skill executor runs and no Intelligence skill fetch happens (TP-05).
- **Composio (R11/M11).** With a Composio key and apps allowed everywhere, no Composio session or tool exists for an incident Dot and only the provider is contacted (TP-06).
- **Research (R9/M12).** With research allowed everywhere, no `search_web`/`read_public_page` is offered (TP-05b), while the same settings do offer them to an ordinary Dot (TP-05b baseline).
- **Memories (R2).** They never reach an incident Dot prompt (TP-05c); the same memory does reach an ordinary one (TP-05c baseline).
- **Per-turn ConnectionService (R10/M8/M9, I5).** Under the stricter R10 ruling (connection tools are not offered to incident Dots), an incident Dot is offered no connection tool. Forged `mail__read_inbox`, `mail__send_mail`, `call_connection_tool` and `request_connection_action` calls each end with a result and no pending call. The MCP server and its host see nothing, and no approval row exists (TP-07). An ordinary Dot is offered the same tools (TP-07 baseline). `ConnectionService.call` refuses an incident Dot on any instance (TP-07b).
- **Per-turn ComputerService (R12/M6/M7, I5).** Agent actions are refused before any supervisor call. An owner action is not mistaken for an agent action (TP-08, and TP-83 through the HTTP route). A configured computer offers no `computer_*` tool to an incident turn (TP-08b).
- **Page prose with fake receipt ids.** A page that contains a receipt id, a source key and an "authorization" instruction does not put that id into the turn's dependency vector; only the sink-registered page receipt appears (TP-09). Client-supplied `system`/`developer` messages are not forwarded (TP-09b). On the team side, a receipt id the attempt never saw is `citation_out_of_scope` at the executor (TP-27) and in the composed loop (TP-61), and nothing is stored.
- **Foreign-mission and superseded citations (I8).** Foreign-mission case: a receipt only mission B read, bound to a real recorded emitting call of A, is `blocked(citation_out_of_scope)` at the action port (TP-62). Another owner's receipt is blocked as a citation, and a snapshot that lists it as support is refused when the call is recorded (TP-62b, F4). Superseded case: a superseded citation cannot publish a finding, since G2 refuses at `coordinator.publishFinding` (TP-63), and a proposal resting on a superseded member never commits while the config row stays byte-identical (TP-64). Note on the design: sources are keyed per owner, environment, Space and resource, not per mission (CONTRACTS rev3 F4b). Two missions of one owner that read the same key therefore share that receipt, so citing it is legitimately in scope for both.
- **The approval callback (M10).** A superseded bound vector gives 409 `stale_evidence`, and nothing is claimed or sent (TP-12). A change between the first check and the claim is refused before the call, and the approval cannot be retried (TP-12b). Current evidence runs the stored request exactly once (TP-12c). ## Remaining risks

- **TOOL_COVERAGE documentation nits (low, outside the guarantee).** R2 says that for ordinary Dots `memories[]` is "recorded", and M8 says ordinary Dots' MCP calls are "instrumented (args/result digests)": both are computed in-process and never persisted. R15 says scheduled turns are "disabled for incident Dots", but they run under the same policy, as section 5 correctly says. R10 does not repeat the "not offered" rule and cites stale line numbers.
- **An incident Dot's forged `request_connection_action` may end its turn.** Its refusing executor sometimes stops the turn after one model call (timing-dependent; TP-71 asserts only the first call). The refusal is visible and nothing executes.
- **Dot-turn page receipts are recorded asynchronously.** The `pageRevision` hook calls `void registerPage(...)`. They are authority-free and nothing in the controlled scope reads `opendots.page/*`.

- **TP-17 attribution is process-local.** After a server restart, or once a thread is evicted (1000 threads, 2000 calls each), replayed evidence is lost and the approval binds `[]`. This fails open for ordinary Dots only.

- **Postcondition gate versus replan.** `team/replan.ts:37-41` lets a replan cancel any non-terminal, non-planner task, including a system-created `postcondition` task. `publish.ts:378-380` then releases the gate it holds. A worker-triggered replan can therefore end a self-write's fresh-evidence verification early. This is deliberate ("never wedge"), not a stale-commit path, and not tested here.
- **Fixture host string.** `FixtureInference` copies `host` from the fixture file (TP-51). Any consumer that decides liveness from `provider.host` and `model.returned` alone, without `provider.mode`, would count a fixture as live.
- **Page receipts are eventual.** `bootstrap.ts` registers page revisions with `void registerPage(...)`. Between a page write and its registration the old receipt is still "current", so M10 is freshness-at-dispatch for page evidence, as W3.3 labelled it.
- **Content-type check.** The upstream content-type check is a substring test (`app.ts:96`). CSRF protection rests on the Origin and `sec-fetch-site` checks and the bearer token (TP-41, TP-42). A same-origin deployment behind a proxy that strips `Origin` would rely on the token alone.
- **Telemetry without a mission.** `GET /telemetry/summary` without `missionId` is not owner-filtered (W4.2 note). One owner today.
- **No incident policy on voice.** `VOICE_API_KEY` is the only gate on the voice path (R14/M16).

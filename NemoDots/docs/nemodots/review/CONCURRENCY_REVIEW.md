# Concurrency devil's advocate review (W5)

Author: concurrency devil's advocate (Claude Code workflow subagent, Sonnet 5.5), 2026-10-17. Package `w5-concurrency-adversary`. Independent of the authors of `actions/`, `ledger/`, `coordinator/` and `watcher/`: every expected outcome below is derived from `ARCHITECTURE.md` sections 4-6, 8 and 14 and `CONTRACTS.md` section 5, and every assertion reads PostgreSQL / Redis with raw SQL and raw commands written in `tests/nemodots/adversarial/concurrency/harness.ts`. No production code was edited.

## How to run

The suite needs the NemoDots stack (PostgreSQL 55432, Redis 56379). It ran on the shared `ci-w1` instance.

```sh
cd NemoDots
# works today (own vitest config in the package):
NEMODOTS_INSTANCE=ci-w1 PATH="$PWD/node_modules/.bin:$PATH" \
  node scripts/nemodots/stack.mjs exec -- cross-env DO_NOT_TRACK=1 \
  vitest run --config tests/nemodots/adversarial/concurrency/vitest.config.ts
# the acceptance command as written:
npm run test:nemodots:db -- tests/nemodots/adversarial/concurrency
```

**The acceptance command as written finds no files**: `vitest.integration.config.ts` includes only `tests/nemodots/integration/**/*.test.ts`, and a second `--config` is rejected by vitest ("Expected a single value for option --config"). Dependency for the integrator (outside this package's allowed files): add `tests/nemodots/adversarial/**/*.test.ts` to the `include` of `vitest.integration.config.ts`, and add `tests/nemodots/adversarial/**` to the `exclude` of `vitest.config.ts`, otherwise `npm test` would pick these stack-needing files up. After that the literal command runs the same 18 files.

Result of the last full run: **18 files, 95 tests passed, 1 expected failure (`it.fails`, finding CW-1), 0 skipped**; six consecutive full runs were stable. Determinism: every race uses the named barriers of `actions/test-hooks.ts`, a latch in a test double, or a real PostgreSQL row lock held by a raw client and observed through `pg_locks` before the competitor is released. Where a race cannot be pinned to one interleaving (lease boundary, SERIALIZABLE contention, mixed stress) it is a bounded randomized loop with invariants that hold for every interleaving, and that is stated below.

## Method notes

- **Deadlock detector.** `harness.ts` wraps every pool of the world so that SQLSTATE 40P01 and 40001 are recorded _before_ `withTransaction` retries them; a retried deadlock cannot hide. A negative control (opposite lock orders on two raw sessions) proves the detector sees a real 40P01.
- **Doubles, all labelled in `harness.ts`.** Missions, tasks and attempts are inserted with SQL; the coordinator used by C9 and C12 is the real one wired to the real ledger validator and a ledger writer that stores edges with the ledger's own functions; the watcher's `SourceReaderPort` reads the real authority rows and its `pauseMission` is a SQL double; `onSelfWriteSettled` is wired to the real `settleFromHistory` as the watcher README requires.
- **Isolation.** `ALTER DATABASE ... SET default_transaction_isolation` before any pool exists runs the production transactions (plain `BEGIN`) at READ COMMITTED, REPEATABLE READ or SERIALIZABLE with no code change.

### CW-1 (low) a mislabelled marker row fails a correct action

- **Command.** `... vitest run --config tests/nemodots/adversarial/concurrency/vitest.config.ts self-write-forgery`
- **Reproduction.** Action A commits `db.pool_max` (history row v2 carries A's id and the expected digest). The trusted application role then writes a history row on `ui.banner_text` that names A as its `caused_by_action_id` (the triggers null the marker for every other role, so nothing but the app role can do this). The watcher walks that key, finds the intent known but for another key, classifies `failed` and calls `onSelfWriteSettled(A, 'failed')`.
- **Expected** (ARCHITECTURE 5.4): an intent is settled from _its own_ row; `after_digest == expected` is `verified`. A's own row is correct, so A must not become `failed`.
- **Actual.** A ends `failed(postcondition_mismatch)`. `settleFromHistory` accepts the verdict without re-checking the intent's own history row. A second test in the same file (`a marker row on another key never VERIFIES the intent`) passes: the unsafe direction (a wrong-key row verifying) is closed.
- **Severity.** Low. No input surface reaches it (all are closed, see the forgery table); it is a consequence-if-the-trust-boundary-slips finding.
- **File.** `src/server/nemodots/actions/settle.ts` (`settleFromHistory`, outcome `failed`): look the intent's own `config_versions` row up and refuse `failed` when its digest matches. Not edited.
- **Test form.** `it.fails`: the run is green while the defence is absent; when fixed the test starts failing and must be flipped to `it`.

### CW-2 (low) SERIALIZABLE liveness

- **Command.** `... vitest run --config tests/nemodots/adversarial/concurrency/vitest.config.ts isolation-levels -t serializable`
- **Reproduction.** Twelve intents on one target admit and commit together with four injector writers on the same row. Escapes (a rejected promise with code 40001) per 30 runs of that scenario: SERIALIZABLE 4, REPEATABLE READ 0, READ COMMITTED 0.
- **Expected.** ARCHITECTURE 5.1 fixes READ COMMITTED and says equivalence under SERIALIZABLE is _proved_: same outcomes. Safety is equivalent: in every run, history versions are gapless, every committed action wrote exactly at `expectedTargetVersion + 1`, at most one action wins a version, and no 40P01 occurred.
- **Actual.** The origin of every escape was `blockIntent` inside the admission transaction (`actions/admit.ts` -> `actions/decision.ts`), which gets the default five attempts of `withTransaction`; commit passes `maxAttempts: 5` explicitly. Under heavy same-row contention SERIALIZABLE exhausts them.
- **Severity.** Low (the production level is READ COMMITTED, where nothing escaped in 30 runs of the same scenario and in six full-suite runs). Relevant only if the isolation level is ever raised.
- **Test form.** The test asserts zero escapes at READ COMMITTED and tolerates only 40001 at the stronger levels; the safety invariants are asserted for every level and every outcome.

### CW-3 (info) residual windows, stated explicitly

**Freshness at admission** (observed sources: `checkout.health`, `redis.stats`, metrics, recent orders, inventory, page snapshots). The guarantee for an observed source is that the receipt is not superseded in the ledger and that `lastConfirmedAt >= now - maxAgeMs` (policy-v1: 120 000 ms for `checkout.health` and `redis.stats`), evaluated with the database clock at admission and again, under the commit locks, at commit. A change of the real world that no watcher or tool has registered cannot be detected. A commit can therefore rest on an observed fact that is no longer true for up to `maxAgeMs` after its last confirmation **plus** the admission-to-commit latency (bounded by the 10 minute intent expiry; the dispatcher lease only bounds who may commit, not for how long the evidence has been unobserved). `c04` pins both halves: the same evidence 1.1 s past its limit between admission and commit is `blocked(evidence_too_old)`, and a world change nobody observed commits (RESIDUAL test).

**Freshness at dispatch** (the Redis flush). Only the controlled authority is re-checked: `claimDispatch` compares `checkout.config_entries['cache.namespace'].version` with the version the flush was committed at, in the claim's own transaction. `c11` proves it refuses an advance that happens before the dispatch, between the commit and the dispatch (barrier `after_commit_before_dispatch`) and inside the claim transaction's own start (barrier `before_lock`). The window that remains is _claim committed -> script executed_ (milliseconds, plus any Redis stall up to `NEMODOTS` Redis budget of 5 s): an advance in that window is not seen and the flush of the old namespace runs (RESIDUAL test in `c11`). `redis.stats`, the observed evidence behind a flush, is not re-read at dispatch; its age is bounded by `maxAgeMs` at commit and by the intent expiry. The Redis fence orders flushes among themselves only and is never consulted for permission. The flush payload namespace is validated for shape only (`^[a-z0-9-]{1,32}$`), not against the active namespace (documented limit in `actions/README.md`; not a race, not tested).

### CW-4, CW-5, CW-6 (info)

- **CW-4.** `nemodots_admin` owns `checkout.config_entries` and can `DISABLE TRIGGER`; with the trigger off a forged marker is stored (test asserts it so the statement is exact). ARCHITECTURE 3 lists the admin URL as held by `stack.mjs`, `migrate.ts`, the test factory and the dev server process; keep it out of any process that handles model-derived input.
- **CW-5.** The ledger does not compare a registered `selfWrite` with the history; only the watcher derives it. `observe_source` executors in `team/` must pass `selfWrite: 'none'` and no `causedByActionId`; the strict tool schemas already give a model no field for it.
- **CW-6.** `lease-boundary.test.ts`: a commit whose call began before the lease lapsed but reaches the row lock after it is refused (`DispatchFenceError`); a commit already holding the lock when the lease lapses completes, and the competing re-admission waits for the same lock and then returns `committed` without taking a new fence. Over 24 randomized A-commit / B-re-admit races around the expiry instant: never two commits, the commit Authorization's fence always equals the fence stored on the intent.

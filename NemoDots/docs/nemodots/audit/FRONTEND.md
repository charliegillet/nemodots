## 2. Routing and view state

There is no router. `App.tsx` (965 lines) owns a single `view` state: `'chat' | 'tasks' | 'memories' | 'space'`.

- **Hash routing exists only for Spaces**: regex `^#/spaces/([^/]+)(?:\/pages/([^/]+))?$` in a `hashchange` effect sets `spaceId`, `pageId`, `view='space'`. Any other hash is ignored (`if (!match) return`). Switching to a non-space view calls `history.replaceState` to clear the hash.
- `src/client/page-navigation.ts#openPageLink(href)` normalises `/#/spaces/...` links and re-dispatches `hashchange` when the hash is unchanged. `ChatTranscript` intercepts Markdown links that start with `/#/spaces/` and routes them through it.
- **Dirty-draft guard**: `dirtyPage` ref + `window.confirm('Leave your unsaved page draft?')` in both `setView` and the hash handler; the handler restores the previously accepted hash when the user cancels.
- Selection state that lives in App: `selectedDot`, `selectedThread`, `spaceId`, `pageId`, `pane` (computer side pane), `navCollapsed`, `mobile` (sidebar drawer), `dialog` (modal union), `taskDetail`, `search`, `prompt`/`pendingPrompt`.
- Breadcrumb text is derived from `view` (`Dots / <dot>`, `Dots / Activity`, `<space> / Pages`, `Dots / Memories`).

**Implication for a mission page**: add `'mission'` to the `view` union, a second hash pattern (`#/missions/:id?`) in the same effect, and the matching breadcrumb branch. The hash effect is the only place that reads `location.hash`, so one edit covers deep links, reloads and sidebar navigation.

## 4. Data access, polling and error surfacing

- `src/client/api.ts`: `api<T>(path, method='GET', body?, signal?)` → `fetch('/api'+path)` with Bearer token from `sessionStorage['opendots-token']`, JSON body, throws `ApiError(message, status)` using the server's `{error}` payload. `authHeaders()` is used for CopilotKit and telemetry. **Every client call goes through this; reuse it.**
- **There is no push transport from the OpenDots server to the client.** Everything is polling:
  - App: `/state` + `/workspace` every 3 s (`refresh`), `/conversations/:id/capture` every 3 s while a thread is selected.
  - `SpaceWorkspace`: `/spaces/:id/pages` every 3 s (merged via `page-snapshots.ts#mergePageSnapshot` to keep local deletes/newer revisions). `SpaceNav` polls the same when expanded.
  - `ComputerPanel`: 4 s `setTimeout` loop, skipped when `document.hidden`, guarded by a `lifecycle` ref with a `revision` counter and an `AbortController`; `ComputerToolCard` polls screenshots every 3 s.
  - `useVoice`: control polls with a grace period for transient failures.
- Error pattern: a string in state, rendered in `<p|div className="chat-error" role="alert">` or the top `.error-banner`. `src/client/poll-notice.ts` is the reusable pure module that dedups poll failures into `{refresh, capture, action}` notices, ignores 401 (handled by the unlock screen), and classifies transport failures (no status / 502 / 504). Unit-tested in `tests/poll-notice.test.ts`.
- Auth states in `App`: 401 → `main.unlock` token form (token kept in session storage only); no data yet → `main.unlock` "Finding your dots…" with Retry.
- Streaming the only SSE in the repo is the OpenAI-compatible _upstream_ stream consumed server-side (fixture `tests/fixtures/model-stream.ts`). Hono's `streamSSE` (`hono/streaming`) is available but unused.

**Implication**: mission "server events with durable IDs, reconnect/replay, dedup" (BUILD_PROMPT §frontend) must be built new. Recommended transport: same-origin **SSE via `fetch` + `ReadableStream` reader** (not `EventSource`), because `EventSource` cannot send the `Authorization` header that the `/api/*` middleware requires when `OWNER_TOKEN` is set, and tokens must never go in query strings. Send `Last-Event-ID` as a request header on reconnect; keep the reducer (ordering, dedup by event id, scope check, replay from a snapshot) in a pure module so it can be unit-tested like `poll-notice.ts`. Keep a 3 s snapshot poll as the fallback so refresh reconstructs from storage even if the stream is down. Avoid WebSockets (Vite proxy lacks `ws: true`; CSP and tests would also need changes).

## 5. Chat / AG-UI streaming hooks (what exists, and why it is BLOCKED here)

Client (`Chat.tsx`, 489 lines, the only consumer of `@copilotkit/react-core/v2` besides the provider in `App.tsx`):

- `CopilotKitProvider runtimeUrl="/api/copilotkit" headers={authHeaders()}` wraps the app **only when `configured`** (`workspace.setup.missing.length === 0`). Otherwise the tree renders without a provider, so **no CopilotKit hook may be called from a component that must work in setup state**.
- `useAgent({ agentId: 'chat-<threadId>', runtimeAgentId: dot.id, threadId })`, `useCopilotKit().copilotkit` → `connectAgent`, `runAgent`, `stopAgent`, `subscribe({onError})` with `CopilotKitCoreErrorCode.AGENT_RUN_*` classification; `agent.subscribe({ onRunErrorEvent, onRunFinishedEvent })`.
- `useHumanInTheLoop` for `review_space_page` (`PageReviewCard`) and the connection-action approval (`ConnectionActionCard`): both cards **read the server's record first** (`/conversations/:id/reviewed-page/:toolCallId`, `/conversations/:id/connection-approvals/:approvalId`, `/connection-actions/:toolCallId`) and refuse to decide until the receipt is loaded; mismatch between the model's args and the server record is treated as a conflict. This is the upstream "approval-then-change" pattern NemoDots must preserve.
- `useRenderTool({ name: '*' })` renders `computer_*` calls as `ComputerToolCard`; `CopilotChatToolCallsView` renders the rest. `ChatTranscript` filters internal voice receipts and scheduled-task messages via marker prefixes in `src/shared/*`.

Server:

- `workspace-routes.ts`: `app.all('/copilotkit/*', (c) => platform.handle(c.req.raw))` → `validateRuntimeScope()` (whole-path allowlist of SDK routes, agent/thread ownership via `workspace.requireThread`) → `createCopilotHonoHandler({ runtime })`.
- `Platform` constructs `CopilotRuntime({ intelligence: CopilotKitIntelligence, agents: dot → new DotAgent(...) })` **only if `config.intelligenceKey` is set**. Without it `platform.handler` is `undefined`, `/api/copilotkit/*` answers `503 Setup required: INTELLIGENCE_API_KEY (or CPK_INTELLIGENCE_API_KEY)`, `POST /conversations` answers 503, and `PageService`/`turn()` throw.
- `DotAgent extends AbstractAgent` (`@ag-ui/client`); `run(input)` returns an rxjs `Observable<BaseEvent>` produced by `BuiltInAgent({ type: 'tanstack' })` with `openaiCompatibleText(model, { baseURL: OPENAI_BASE_URL, api: 'chat-completions', maxRetries: 1 })`, `max_completion_tokens: 2200`, a 100 ms permission watcher that aborts the run when settings/Dot permissions change, and `AGENT_RUN_TIMEOUT_MS` (default 90 s). This is where NemoDots' "provenance at central model/context construction" hook belongs on the chat path (dependency for the backend builder, not a frontend file).
- `headless.ts#runThreadTurn` uses `IntelligenceAgent` from `@copilotkit/core` for server-side turns; it also requires Intelligence.

**Status in this run**: LEAD_NOTES marks Intelligence BLOCKED. Therefore the chat column, page chat (`PageConversation` shows "Connect your assistant" with a Settings button), new-conversation composer, voice and scheduled tasks are all in setup state; `.mode-badge` reads `SETUP REQUIRED`. The mission page **must not** depend on `CopilotKitProvider`, `useAgent` or the AG-UI runtime; it should use plain `api()` + its own event stream, and honestly label chat as unavailable. Reusing OpenDots' AG-UI streaming for mission events is not viable in this environment.

## 6. Setup-state UI (reuse as-is)

- Source of truth: `GET /api/workspace` → `setup: SetupStatus { intelligence, model, browser, voice, composio, slack, missing[] }` (`platform-config.ts#setupStatus`). `missing` lists env names: Intelligence key, `OPENAI_API_KEY`, `OPENAI_MODEL`.
- `GET /api/state` also returns `{ mode: 'sample' | 'live', configured }` from the research config; the UI badge uses `workspace.setup` not `state.mode`.
- Surfaces: `.mode-badge` (`SELF-HOSTED` / `SETUP REQUIRED`; CSS also defines `.mode-badge.live`), `.setup-card` under the empty chat, `.sidebar-empty`, disabled composer/starter buttons, Settings dialog `.config-note` listing `<code>` env names, `.connection-note` (Slack status + online dot), `trackSetupStep()` telemetry (`POST /api/setup-telemetry`, server rejects a `step_viewed` that does not match its own state; `DO_NOT_TRACK=1` in tests).
- Missing from upstream: there is no notion of **Live / Fixture / Blocked** per subsystem. NemoDots needs its own status endpoint (provider reachable, model id verified via `/v1/models`, Postgres 55432, Redis 56379, checkout 4510, Intelligence) and a badge set that extends `.mode-badge` (e.g. `.mode-badge.live`, `.fixture`, `.blocked`) with **visible text**, never colour alone.

## 7. Styling system

- Plain global CSS, two files: `style.css` (4,282 lines) and `editor.css` (1,225 lines, Spaces library/editor; also defines `.sr-only`). Flat kebab-case class names, component-prefixed (`.computer-*`, `.library-*`, `.document-*`, `.connection-*`, `.page-review-*`, `.call-*`). No CSS modules, no Tailwind, no inline-style conventions beyond small dynamic values (e.g. indentation `paddingLeft` in `SpaceNav`).
- Tokens: `:root { --ink:#333641; --muted:#8c8d97; --line:#e9e8e6; --blue:#7285d5; --blue-dark:#5269bb; --lavender:#eeeffa }`, overridden by `.template-app { --line:#e7e7e7; --blue:#282828; --blue-dark:#111; --lavender:#f1f1f1; --accent:#242424; --accent-hover:#000; --text-secondary:#6b6b6b; --disabled-bg:#ececec; --disabled-ink:#9a9a9a }`; `editor.css` adds `--document-ink/--document-muted/--document-line`. Palette is warm greys and near-black accent; many literal hex colours are used directly instead of tokens. Typography is the system stack (`-apple-system, Segoe UI`), base 14 px, with very small labels (8–11 px eyebrows, badges, status pills).
- **Dark mode is generated at build time** by the PostCSS plugin `src/build/dark-theme.ts` (wired in `vite.config.ts`): every rule with colour declarations gets a twin under `:root[data-theme='dark']` with OKLab lightness flipped (white→`#1b1b1b`), hue kept, shadows de-tinted, and text/background pairs forced to ≥ 4.5:1. Only **hex literals and `white`/`black`** are mapped (`url()` skipped); `rgb()/hsl()/oklch()` values are left untouched, so **use hex colours** in new CSS. Wrap intentionally dark surfaces in `/* theme: fixed .selector */ … /* theme: end */` (see `.call-view`). `public/theme.js` applies `data-theme` before first paint; `theme.ts` handles the `system|light|dark` preference in `localStorage['opendots-theme']` and the Settings dialog's `.segmented` radio group. `tests/dark-theme.test.ts` covers the plugin. A charcoal/slate + electric-green mission palette will be lightness-flipped in dark mode unless placed in a fixed block; decide deliberately.
- Icons: `lucide-react` (sizes 13–21). Markdown rendering: `react-markdown` (+ `remark-gfm` in `PageReviewCard`) with `img` and `a` component overrides; react-markdown escapes raw HTML by default, which is the sanitisation primitive to reuse for untrusted model text.
- Reusable visual primitives (class → purpose): `.eyebrow` (uppercase label), `.page-heading` (title block with optional primary button), `.primary`/`.full`, `.icon-button`, `.text-button`, `.quiet-button`, `.status.{completed|running|failed|interrupted|paused}` (pill with dot + text), `.mode-badge(.live)`, `.task-row` (button row with icon/title/meta/status/chevron), `.task-detail-card`, `.task-controls`, `.memory-grid`/`.memory-card`, `.large-empty`, `.notice`, `.error-banner`, `.chat-error`, `.setup-card`, `.config-note`, `.permission-row`, `.segmented`, `.search-box`, `.inline-computer` + `.tool-state(.failed)`, `.page-review-card`, `.connection-*`, `.modal*`, `.sidebar-empty`, `.sr-only`.

## 8. Component conventions

- One component per file, named exports (`RichEditor` is the only default export, loaded with `lazy()`). Props typed inline as an object literal; callbacks named `onX`; `key={id}` used to remount on identity change (`Chat key={thread.id}`, `PageDocument key={page.id}`).
- Data loading inside `useEffect` with an `active`/`cancelled` flag and, for anything long-lived, an `AbortController`; polling via `setInterval` (simple) or self-rescheduling `setTimeout` with `document.hidden` check (ComputerPanel) — the latter is the better pattern to copy.
- Pure logic lives in small modules next to the component and is unit-tested: `poll-notice.ts`, `page-review-decision.ts`, `page-snapshots.ts`, `page-chat-requests.ts` (request-scope guard class), `chat-composer.ts`, `editor/autosave.ts` (`PageAutosave` store with `subscribe/getSnapshot` for `useSyncExternalStore`), `page-context.ts`.
- Shared types: `src/shared/types.ts` (State, WorkspaceState, Dot, Conversation, Task…), `src/shared/*-types.ts` with zod schemas shared by server tools and client cards. The client imports **type-only** from `../server/pages` (`Page`), so client→server type imports are an accepted convention; runtime imports are not.
- Accessibility baseline the audit expects to be preserved: `aria-label` on every icon button, `aria-current="page"` on active nav, `role="alert"` for errors, `role="status"`/`aria-live="polite"` for save status, `aria-expanded`/`aria-controls` on disclosures, focus trap + Escape in dialogs, `.sr-only` labels, keyboard menu navigation in `DocumentMenu`, non-colour text on every status pill.
- Honesty conventions already in the codebase and required by BUILD_PROMPT: `ResultPane` labels fixtures `FICTIONAL SAMPLE BRIEF` with a `.sample-note`; `ComputerToolCard` never marks a nonzero exit as success and labels unfinished calls `Interrupted` after a run ends; `ConnectionActionCard` shows the server's record of the action, not the model's description.

## 9. How server events reach the client today (summary)

| Path                                       | Mechanism                                                                                 | Durable IDs / replay                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------------------- |
| Chat turns                                 | AG-UI events over CopilotKit runtime (`/api/copilotkit/agent/:id/run                      | connect`) → Intelligence persists threads | SDK-level; **BLOCKED without Intelligence** |
| Workspace/state/tasks/pages/computer/voice | 3–4 s polling of REST snapshots                                                           | none; snapshots are authoritative         |
| Scheduled task events                      | `GET /tasks/:id` returns `events[]` with integer ids, rendered as `.muted` lines (last 6) | integer ids exist but no streaming        |
| Approvals / receipts                       | client fetches the server receipt by `toolCallId`/`approvalId` before acting              | server receipt is authority               |

Nothing in the client subscribes to a server-sent stream. Gate 7's "refresh/reconnect mid-run with dedup and reconstruction" has no upstream implementation to extend; it must be added (see §4 recommendation).

## 12. Recommendation: where the mission page lives and what to reuse

### Placement

- **One new top-level view, `'mission'`, inside the existing App shell** (not a separate React app, not a Space page). Deep link `#/missions/:missionId?` handled in the same `hashchange` effect as Spaces; sidebar `.nav-item` "Missions" (with active count `<small>`) plus an icon-rail button; breadcrumb `NemoDots / Mission`. Rendered in `main.main-content` with `.page-heading` so it inherits the Activity/Memories look, then a dedicated grid below.

## 5. CopilotKit Intelligence — what fails without it, what still works

Verified by reading `src/server/index.ts`, `platform.ts`, `platform-config.ts`, `app.ts`, `dot-agent.ts`, `headless.ts`, `learning.ts`, `src/client/App.tsx`, `docs/SETUP.md`, `README.md`.

Boot behavior with no Intelligence key (`INTELLIGENCE_API_KEY`/`CPK_INTELLIGENCE_API_KEY` empty):

- The server **starts** (`Platform` constructor returns early at `platform.ts:49`; `this.intelligence` stays undefined). Binding to 127.0.0.1 needs no `OWNER_TOKEN`. SQLite (`node:sqlite`) workspace store opens at `DATABASE_PATH` (default `data/opendots.sqlite`).
- `setupStatus()` (`platform-config.ts`) reports `missing: ["INTELLIGENCE_API_KEY (or CPK_INTELLIGENCE_API_KEY)", "OPENAI_API_KEY", "OPENAI_MODEL"]` as applicable and `intelligence:false`. The client computes `configured = setup.missing.length === 0` → `setupStep = 'setup_required'`; the composer placeholder becomes "Your first conversation starts after setup."
- **Still works:** Spaces, pages (Tiptap editor, page outline/review), Dot configuration, settings dialog, owner-token/origin protections, scheduled-task CRUD UI, static build/serving, all 344 upstream tests.
- **Fails / unavailable (BLOCKED):** every conversation (`/api/copilotkit` runtime requires `intelligenceKey` + model, `dot-agent.ts:121-131` throws "Intelligence and model configuration are required."), thread creation (`platform.ts:155`), history (`platform.ts:171`), scheduled-task execution (`app.ts:130` returns 503 "Setup required"; `index.ts` runner needs a thread), headless/voice/Slack turns (`headless.ts runThreadTurn` queries the Intelligence runtime `/info` and requires `mode: "intelligence"`), Automatic Learning (`learning.ts` selector + per-Dot `learningContainerId`, Intelligence-side containers), Channels (Slack). TEST_PROMPT gate 4.8 (reload a conversation after a real Intelligence turn) is BLOCKED.
- Obtaining a key requires `npx copilotkit@latest login` (account sign-in) for hosted, or Docker Desktop + sign-in for the local evaluation stack. Both are outside this run (account interaction; no Docker daemon).

Consequences for NemoDots (task dependencies):

1. Mission control must not route through `/api/copilotkit`, Intelligence threads, or `DotAgent`. It needs its own authenticated Hono routes (reuse the `/api/*` origin/owner middleware from `app.ts`), its own Nemotron adapter, and its own event stream.
2. `setupStatus.missing` conflates Intelligence and model configuration. The mission page must show a NemoDots-specific status (Nemotron: live/blocked; Intelligence: blocked, with the honest label "conversations unavailable") rather than flipping the upstream `configured` flag. Changing upstream `setupStatus` semantics breaks `tests/intelligence-key.test.ts` and friends.
3. The upstream SQLite store remains the authority for Spaces/pages/Dots; NemoDots facts go to PostgreSQL. Page copies are projections (BUILD_PROMPT).

## 9. Local native PostgreSQL 16 / Redis 8 plan (no Docker)

Both services were **probed live and stopped** (nothing left listening; probe data removed, logs kept):

- `initdb -D .local/audit-probe/pg --auth=trust --username=nemodots_admin --encoding=UTF8 --no-locale` → exit 0 (`audit/probe-initdb.log`).
- First `pg_ctl start` on 55432 **failed**: `FATAL: postmaster became multithreaded during startup — HINT: Set the LC_ALL environment variable to a valid locale` (`audit/probe-postgres-55432.log`). This shell has `LANG`, `LC_ALL`, `LC_CTYPE` all empty. **The stack script must export `LC_ALL=C` (or `en_US.UTF-8`) before `pg_ctl`.** With `LC_ALL=C` it started (`PostgreSQL 16.13 (Homebrew) on aarch64-apple-darwin24.6.0`, port 55432, `max_connections=100`, `shared_buffers=16384` pages = 128 MB, `wal_level=replica`, default isolation `read committed`), accepted a `SERIALIZABLE` transaction with `FOR UPDATE`, and `pg_ctl -m fast stop` returned 0.

```text
  redis/redis.log, redis/redis.pid
```

- Postgres start: `LC_ALL=C pg_ctl -D .local/postgres/data -w -l .local/postgres/postgres.log -o "-p 55432 -k $PWD/.local/run -c listen_addresses=127.0.0.1" start`; health `pg_isready -h 127.0.0.1 -p 55432`; stop `pg_ctl -D ... -m fast -w stop`. Never use `-m immediate` in normal flow; never run `pg_ctl` against a data dir you did not create.
- Auth: `initdb --auth-local=trust --auth-host=scram-sha-256` then create least-privilege roles with passwords generated into `.local/` (never into git or logs): suggested `nemodots_admin` (migrations, owner), `nemodots_app` (ledger/coordinator DML), `nemodots_checkout` (checkout API, its own schema only), `nemodots_injector` (fault injector; may only call the controlled mutation path), `nemodots_verifier` (read-only). BUILD_PROMPT requires source/version rows and the supported configuration targets to share **one database and transaction boundary**, so plan one database (e.g. `nemodots`) with schemas (`ledger`, `coordinator`, `checkout`) and schema-scoped grants rather than separate databases — architect's decision to confirm in ARCHITECTURE.md.
- Tests: create `nemodots_test_<random>` databases on 55432 only, run migrations from empty, drop only those. Guard every test helper with an assertion that the port is 55432 (refuse 5432).
- Redis: `redis-server --port 56379 --bind 127.0.0.1 --dir $PWD/.local/redis --daemonize yes --pidfile ... --logfile ... --appendonly yes` (persistence is optional; BUILD_PROMPT says losing Redis must not lose authoritative work, so `--save ""` is also acceptable and makes "lose Redis" tests simpler). Health `redis-cli -p 56379 ping`; stop `redis-cli -p 56379 shutdown`. Namespace keys per environment (`nemodots:<env>:...`); tests use dedicated logical DB indexes (`SELECT 9..15`) and `FLUSHDB` on 56379 only; never `FLUSHALL`, never port 6379.
- Checkout API: port 4510 (LEAD_NOTES), separate Node process started/stopped by the same script, with its own `nemodots_checkout` credentials read from `.local/` or `.env`, never from the model-visible toolset.
- Process ownership: the stack script writes pid files under `.local/run/`; agents stop only pids they started (or call the script's `stop`).

# Track 3 Research Synthesis: "Version N+1" — Self-Improving & Self-Evolving Multi-Agent Teams on Crusoe Managed Inference

> **Hackathon Prompt:** *"Most agent teams are exactly as good on run 100 as on run 1. Build an agent team on Crusoe Managed Inference that improves itself over time: after each run it reviews what worked and what didn’t, then rewrites its own prompts, playbooks, tools, or team structure, and keeps a change only if it measurably helps. How can a team turn its own history into a better version of itself, and prove it with a before-and-after score on tasks it hasn’t seen?"*

---

## 1. Executive Framing & The Crusoe Managed Inference Reference Architecture

A truly self-improving multi-agent system ("Version $N+1$") must distinguish **within-run adaptation** (retries, self-correction, or dynamic RAG that vanish when the episode ends) from **persistent cross-run evolution**, where execution traces produce a versioned candidate mutation to the agent's durable state—its prompts, procedural playbooks, executable skills/tools, or multi-agent routing graph—and a **strict evaluation gate** decides whether Generation $N+1$ replaces Generation $N$ ([Arize Self-Improving Agents Guide](https://arize.com/resources/self-improving-agents/); [arxiv:2606.28374](https://arxiv.org/abs/2606.28374)).

Crucially, **weight fine-tuning is neither required nor optimal for run-by-run recursive evolution**. Across the 2025–2026 literature—including **Nous Research's Hermes Agent Self-Evolution** ([GitHub Repo](https://github.com/NousResearch/hermes-agent-self-evolution)), **RSEA** ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)), **Maestro** ([arxiv:2509.04642](https://arxiv.org/abs/2509.04642)), **STEVE** ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)), **GSO** ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)), and **HyperAgents** ([arxiv:2603.19461](https://arxiv.org/abs/2603.19461))—the dominant paradigm freezes the foundation model weights and evolves the **symbolic/code scaffold** (the "Agent Genome") via API calls.

### Native Alignment with Crusoe Managed Inference
In September 2026, Crusoe published *"The open agent stack: Running Nous Research’s Hermes Agent on Crusoe Managed Inference"* ([Crusoe Blog](https://www.crusoe.ai/resources/blog/running-nous-researchs-hermes-agent-on-crusoe-managed-inference)), demonstrating a two-tier model architecture over Crusoe's OpenAI-compatible endpoint (`https://api.inference.crusoecloud.com/v1`) that maps directly to Track 3:
1. **Primary Actor / Meta-Optimizer Model (`moonshotai/Kimi-K2.6`, 256K context):** Handles complex multi-agent planning, trace reflection, and GEPA/TextGrad candidate synthesis across long execution histories.
2. **Auxiliary Curator / Fast Verifier Model (`nvidia/Nemotron-3-Nano-Omni-Reasoning-30B-A3B`, ~3B active MoE params, 262K context):** Configured in Hermes's `auxiliary.curator` slot (introduced in Hermes v0.12.0) to execute background skill rubric grading, trajectory classification, deduplication, and canary validation at ultra-low latency and cost.
3. **Crusoe MemoryAlloy KV-Cache Reuse:** Because self-evolution requires running candidate agent variants in parallel across validation minibatches (`batch_runner.py`), Crusoe's MemoryAlloy prefix/KV-cache sharing slashes the cost of parallel validation rollouts—provided mutations respect prompt-caching boundaries and are deployed only at session/version boundaries rather than hot-swapped mid-conversation ([Hermes Self-Evolution PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md)).

## 2. Concrete Algorithms & Mechanisms for the "Version N+1" Loop

### (A) Post-Run Reflection & Credit Assignment Across Multi-Agent Traces

When a multi-agent team fails or acts inefficiently on Run $N$, a scalar reward ($0$ or $1$) tells the optimizer *that* the team failed, but not *which agent, prompt rule, tool description, or handoff edge* caused the failure. State-of-the-art trace attribution solves multi-agent credit assignment through four concrete mechanisms:

1. **Trace / OPTO Execution-Graph AutoDiff ([arxiv:2406.16218](https://arxiv.org/abs/2406.16218)) & TextGrad ([arxiv:2501.16673](https://arxiv.org/abs/2501.16673)):**
   - Records the multi-agent run as a Directed Acyclic Graph (DAG) of operations $\mathcal{G} = (\mathcal{V}, \mathcal{E})$, where nodes are agent calls/tool executions and edges are message payloads.
   - Instead of numeric derivatives, an LLM critic computes textual feedback $\frac{\partial \mathcal{L}}{\partial v}$ starting from the terminal verifier error or rubric score and propagating backward along only the causal ancestors of the failed output.
2. **Textual Equilibrium Propagation (TEP) to Prevent Exploding/Vanishing Textual Gradients ([arxiv:2601.21064](https://arxiv.org/abs/2601.21064)):**
   - **Failure Mode of Naive TextGrad in Deep Multi-Agent Chains:** Chen et al. (2026) prove that global textual backpropagation suffers from two depth-scaling pathologies in long-horizon compound systems: *(i) exploding textual gradients* (critique length grows exponentially with hop depth $D$, amplifying evaluator bias) and *(ii) vanishing textual gradients* (upstream agents receive over-compressed, vague feedback after multiple LLM summarization hops).
   - **TEP Algorithm:** Replaces global backward chains with two local phases:
     - *Free Phase:* Local node critics iteratively refine each agent's output/state locally until reaching a stationary critique equilibrium.
     - *Nudged Phase:* Applies proximal prompt edits with bounded modification intensity driven by forward-signaled task-level objectives rather than multi-hop backward chains, consistently outperforming global TextGrad as agent depth scales ([arxiv:2601.21064](https://arxiv.org/abs/2601.21064)).
3. **TRACE: Multi-Component Causal Trajectory Attribution ([arxiv:2608.09153](https://arxiv.org/abs/2608.09153)):**
   - Extends textual attribution from monolithic prompts to **heterogeneous context sources** (system prompts, `SKILL.md` procedural skills, RAG knowledge bases, and tool schemas).
   - Mines explicit verifier failures and *implicit dissatisfaction signals* (retries, tool errors, user corrections, abandonment).
   - Uses **Exploratory Verification**: the diagnostic agent actively inspects the underlying context files to classify whether the root cause is a **content gap** requiring `CREATE` (a missing skill/rule) or **stale/wrong instructions** requiring `UPDATE`, achieving **96% operation classification accuracy**, **72.7% root-cause attribution accuracy**, and **82% end-to-end fix effectiveness** across 16-node execution graphs ([arxiv:2608.09153](https://arxiv.org/abs/2608.09153)).
4. **STEVE's Error-Driven Refinement Filter ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)) & GSO's First-Fault Localization ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)):**
   - **Critical Rule — Never Compute Gradients on Passing Runs:** Xu et al. (2026) demonstrate in **STEVE** ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)) that generating textual gradients from already-correct examples injects destructive noise that drops GSM8K accuracy from **86.2% (error-only) to 82.5% (full dataset) and 76.5% (correct-only)**. Updates must be triggered *exclusively* on failure or sub-threshold traces $\mathcal{D}_{\text{hard}}(p_t) = \{(x,y) \mid \mathcal{S}(M_{\text{exec}}(p_t, x), y) < \tau\}$.
   - **Single-Component Blame Assignment (GSO):** In **Generalizable Skill Optimization** ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)), when a trajectory fails, the trace analyzer identifies the *earliest diverging step* in the execution log and maps it to **exactly one modular section $m_k \in \{m_1, \dots, m_6\}$** (e.g., $m_1$: task reading, $m_2$: tool selection, $m_3$: procedure writing, $m_4$: result checking, $m_5$: error diagnosis, $m_6$: bounded repair). Only that single blamed module $m_k$ is mutated per iteration, preventing a localized failure from corrupting the rest of the team's instructions.

### (B) Mutating the "Agent Genome" (Prompts, Playbooks, Tools, and Team Topology)

Rather than treating an agent team as an unstructured blob of text, Track 3 architectures formalize the **"Agent Genome"** as a versioned tuple $\mathcal{G}_t = (S_t, \mathcal{K}_t, \mathcal{T}_t, G_t)$ governed by explicit protocol schemas (such as the **Autogenesis Protocol / RSPL**, [arxiv:2604.15034](https://arxiv.org/abs/2604.15034)). Here is how each layer is mutated:

#### 1. Three-Layer Natural-Language State & Metaskills (RSEA & GSO)
- **RSEA's 3-Layer State ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)):** Nguyen et al. (2026) show that flat prompt optimization conflates distinct knowledge types. RSEA separates the evolved context into a compact triple $s = (\textsc{strategy}, \textsc{skills}, \textsc{playbook})$:
  1. `strategy`: An imperative preamble ($\le$ a few sentences) defining high-level policy priorities.
  2. `skills`: A concise library of conditional rules / reusable sub-routines (`IF condition THEN action`).
  3. `playbook`: Ordered step-by-step procedures distilled from verified successful trajectories.
  - Across generations, the meta-optimizer inspects a balanced sample of successful and failed trajectories from $D_{\text{evolve}}$ and performs a holistic rewrite $s_{g-1} \to \tilde{s}_g$, keeping total injected preamble under a few hundred tokens. On ALFWorld, RSEA lifts single-pass success from **64.6% (ReAct) to 69.3%** ($p=0.015$) and reaches **79.4% with retry**, beating Reflexion, GEPA, AWM, ACE, and Dynamic Cheatsheet ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)).
- **GSO's Metaskill vs. Ephemeral Task Skill ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)):** Piao et al. (2026) prove that directly mutating a shared static skill $s$ across training tasks causes **skill overfitting** (hard-coding specific column names, filenames, or one-off patches into global rules). Instead, GSO evolves a **6-part Metaskill $m = (m_1, \dots, m_6)$**—a reusable guide for *how to write a task-specific skill*. At runtime on an unseen task $x$, the agent invokes $s_x = C(m, x)$ to synthesize a bespoke execution checklist tailored to $x$'s actual files and tools, executes $x$, and **discards $s_x$ after the run**. Only the abstract metaskill $m$ persists across runs, beating all five self-evolving skill baselines (SkillGen, Trace2Skill, SkillOpt, EvoSkill, GEPA) on all 6 benchmarks by **+4.3 to +22.5 percentage points** ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)).

#### 2. Reflective Pareto Mutation & Tiered Artifact Evolution (DSPy + GEPA & Nous Hermes Self-Evolution)
- **GEPA (Genetic-Pareto Prompt Evolution, ICLR 2026 Oral, [GitHub](https://github.com/gepa-ai/gepa), [dspy.GEPA](https://dspy.ai/diving-deeper/choosing-an-optimizer/)):**
  - Unlike **MIPROv2** (which uses Bayesian optimization over candidate instructions and bootstrapped few-shot demos and typically requires 200+ examples), **GEPA** reads full execution traces (tool calls, error logs, evaluator critiques), reflects in natural language on *why* a minibatch failed, proposes targeted mutations, and maintains a **Pareto frontier** of non-dominated candidates across multiple objectives (accuracy, token cost, conciseness). GEPA achieves a **~13% aggregate lift over MIPROv2** and **outperforms GRPO reinforcement learning with up to 35x fewer rollouts** (working with as few as 3–20 examples) ([Future AGI DSPy 2026 Comparison](https://futureagi.com/blog/dspy-optimizers-explained/); [o-mega 2026 Guide](https://o-mega.ai/articles/self-improving-ai-agents-the-2026-guide)).
- **Nous Research's `hermes-agent-self-evolution` 4-Tier Mutation Hierarchy ([PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md)):**
  - **Tier 1 — Procedural Skills (`SKILL.md`, Lowest Risk, Highest Leverage):** Wrapped as a `dspy.Module`, evaluated in parallel via `batch_runner.py`, mutated via `dspy.GEPA`, and periodically cleaned up by Hermes's **Autonomous Curator** (which grades skills by usage/rubric every cycle, merges near-duplicates, and prunes dead skills).
  - **Tier 2 — Tool Descriptions (`tools/registry.py`, Medium Risk):** Treats tool selection as a multi-class classification problem; GEPA mutates tool `description` strings ($\le 500$ chars) based on tool-misselection traces (e.g., choosing `terminal(grep)` instead of `search_files`), while freezing JSON schema parameter names/types.
  - **Tier 3 — System Prompt Sections (`prompt_builder.py`, Higher Risk):** Parameterizes modular sections (`DEFAULT_AGENT_IDENTITY`, `MEMORY_GUIDANCE`, `SKILLS_GUIDANCE`) as `dspy.Signature` fields with a hard $\le 20\%$ growth cap.
  - **Tier 4 — Executable Tool & Harness Code (Darwinian Evolver / DGM / MGM):** Evolves Python tool implementations as `GitBasedOrganism` branches tested against `pytest` + benchmark gates ([PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md)). In the **Darwin Gödel Machine** ([arxiv:2505.22954](https://arxiv.org/abs/2505.22954)), open-ended code mutation improved SWE-bench from **20.0% to 50.0%**, and the **Mendel Gödel Machine (MGM)** ([arxiv:2608.07645](https://arxiv.org/abs/2608.07645)) introduced **reaction-norm mutation** (editing an agent using trajectories across multiple tasks simultaneously) and **cross-lineage hybridization** (recombining code from distinct branches of the archive tree), boosting SWE-bench Verified from **68.3% to 78.3%** and Polyglot from **50.8% to 93.2%** within 200 evaluations on a 35B Qwen backbone.

#### 3. Mutating Multi-Agent Team Structure & Topology (Maestro, TacoMAS, MANTA, ADAS)
When prompt tuning hits a structural ceiling (e.g., an agent loops because it lacks a dedicated Critic node, or context overflows because a Planner and Executor aren't separated), the system must mutate its **team graph $G = (V, E)$**:
1. **Maestro's Block-Coordinate Graph + Config Optimizer ([arxiv:2509.04642](https://arxiv.org/abs/2509.04642)):**
   - Models the agent team as a typed stochastic computation graph $G = (V, E)$ with node configurations $C = \{c_v\}_{v \in V} \cup \{\alpha_e\}_{e \in E} \cup \{\beta_v\}_{v \in V}$ (where $c_v$ includes model choice $\theta_v$, prompt $\rho_v$, and toolset, and $\alpha_e, \beta_v$ are edge adapters and merge operators).
   - Alternates between two budgeted steps guided by trace critiques:
     - **C-step (Config Update):** Fix topology $G^{(t)}$, optimize node prompts/models/tools $C^{(t+1)}$ under rollout budget $B_t$.
     - **G-step (Graph Update):** Fix configuration $C^{(t+1)}$, apply trust-region structural edits to $G^{(t+1)}$—inserting validator/critic nodes, adding explicit memory state nodes, synthesising numeric-computation tools, or rewiring conditional routing edges—under graph complexity constraint $\Omega(G) \le \tau$.
   - **Empirical Lift:** Maestro beats MIPROv2 by **+12.0%**, GEPA by **+4.9%**, and GEPA+Merge by **+4.86%** on IFBench and HotpotQA (reaching **72.0% vs. 38.0% initial and 69.0% GEPA** on HotpotQA with far fewer rollouts), and improves real-world Interviewer and RAG agents by **+65.7% with joint graph+config optimization** vs. **+41.9% for config-only** ([arxiv:2509.04642](https://arxiv.org/abs/2509.04642)).
2. **TacoMAS: Fast-Slow Two-Timescale Co-Evolution ([arxiv:2605.09539](https://arxiv.org/abs/2605.09539)):**
   - Xu et al. (2026) prove theoretically and empirically that mutating agent prompts/capabilities and multi-agent topology at the same frequency causes **coordination instability**.
   - **Two-Timescale Rule:** TacoMAS runs a **Fast Capability Loop** (updating role-specific prompts/skills after every run/batch via trajectory feedback) coupled with a **Slow Topology Loop** (where a meta-LLM executes birth-death structural operations—agent addition, agent removal, and communication edge rewiring—only every $K$ runs once capability updates plateau). This fast-slow separation drives the team to a stable equilibrium and beats ~20 multi-agent baselines by **+13.3% average improvement** ([arxiv:2605.09539](https://arxiv.org/abs/2605.09539)).

### (C) Strict Acceptance Gating: Keeping a Change ONLY If It Measurably Helps

The single most important finding in the 2026 self-evolving agent literature is from **RSEA ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374))**:
> *"The reliability of context evolution comes less from the artifact being evolved and more from the selection gate that decides whether to commit it. An evolution loop that commits whatever it produces inherits the variance of its own rewrites; one that commits a change only when it improves held-out performance cannot do worse than not evolving at all."*

To guarantee **monotone-safe improvement** (Version $N+1$ is never worse than Version $N$), an agent team should enforce a **4-Stage Acceptance Gate** before promoting any candidate genome $\mathcal{G}_{\text{cand}}$:

#### Gate 1: Hard Structural, Budget & Test Invariants (Fast Pre-Filter, Zero Inference Cost)
Borrowed from Nous Research's `hermes-agent-self-evolution` (`evolution/core/constraints.py`, [PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md)):
- **Unit & Schema Tests:** `pytest tests/ -q` must pass 100%; tool JSON schemas and function signatures must remain untouched.
- **Anti-Bloat Size Caps:** Skills $\le 15\text{KB}$, tool descriptions $\le 500\text{ chars}$, system prompt sections $\le +20\%$ of baseline length, plus a continuous length penalty in the fitness score.
- **Semantic Drift Floor:** Cosine similarity or rubric check ensuring the mutated skill/prompt has not drifted from its core role.

#### Gate 2: STEVE Regularized Verification on the Preservation Pool ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716))
- **Problem:** Optimizing on recent failures $\mathcal{D}_{\text{hard}}$ causes over-specialization that breaks simple or previously mastered tasks (catastrophic forgetting in prompt space, analogous to weight drift in continual learning).
- **Mechanism:** Maintain a **Generalization Preservation Pool** $\mathcal{D}_{\text{preserve}} \subset \{(x,y) \in \mathcal{D}_{\text{train}} \mid \mathcal{S}(M_{\text{exec}}(\mathcal{G}_0, x), y) \ge \tau\}$ of tasks that previous versions solved correctly. At generation $t$, draw a subsample $\mathcal{D}_{\text{sample}}^{(t)}$ ($k=20$) and compute the regularized objective:
  $$J(\mathcal{G}_{\text{cand}}) = \text{Improvement}(\mathcal{G}_{\text{cand}}, \mathcal{D}_{\text{hard}}) - \lambda_t \cdot \max\big(0, \text{Regression}(\mathcal{G}_{\text{cand}}, \mathcal{D}_{\text{sample}}^{(t)})\big)$$
  where $\lambda_t = 1.5 + 0.1t$ is a linearly annealing conservatism schedule that penalizes regressions more heavily as the agent matures. Accept $\mathcal{G}_{\text{cand}}$ only if $J(\mathcal{G}_{\text{cand}}) > 0$ ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)).
- **Ablation Proof:** Removing Regularized Verification drops STEVE's accuracy from **86.2% to 84.1%** on GSM8K, **93.2% to 91.5%** on StrategyQA, and **95.7% to 92.2%** on Object Counting ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)).

#### Gate 3: GSO Asymmetric Repair-vs-Regression Gate on Disjoint Validation Split ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2))
- Evaluate both incumbent $\mathcal{G}_t$ and candidate $\mathcal{G}_{\text{cand}}$ on a disjoint validation set $\mathcal{D}_{\text{val}}$ (which the proposer/reflector **never reads**).
- Let $R$ be the set of **Repairs** (tasks in $\mathcal{D}_{\text{val}}$ that $\mathcal{G}_t$ failed and $\mathcal{G}_{\text{cand}}$ passed) and $B$ be the set of **Regressions / Broken tasks** (tasks that $\mathcal{G}_t$ passed and $\mathcal{G}_{\text{cand}}$ failed).
- **Strict Asymmetric Acceptance Rule:**
  $$u(\mathcal{G}_{\text{cand}}, \mathcal{G}_t) = |R| - 2|B| > 0$$
  A candidate is committed **if and only if it repairs more than twice as many validation tasks as it breaks** (for continuous rubric scores, $\sum \Delta_{+} - 2\sum \Delta_{-} > 0$) ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)).
- **Cross-Tool Non-Cannibalization Check:** When mutating tool descriptions or routing rules, evaluate *all* tools jointly on $\mathcal{D}_{\text{val}}$ and reject if any individual tool's selection accuracy regresses ([Hermes PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md)).

#### Gate 4: Strict Keep-Better Tie-Breaking & Git Lineage Commit ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374))
- **Strict Inequality ($>$ not $\ge$):** RSEA proves that non-strict updates ($\ge$) allow candidates that merely tie on a small validation draw to replace simpler baselines, introducing context distraction on unseen tasks. If $\text{Score}(\mathcal{G}_{\text{cand}}, \mathcal{D}_{\text{val}}) \le \text{Score}(\mathcal{G}_t, \mathcal{D}_{\text{val}})$, the gate **rejects the mutation and retains $\mathcal{G}_t$** (falling back to the clean baseline when evolution does not strictly help) ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)).
- **Theoretical Guarantee (Chojecki's Variance Inequality, [arxiv:2512.02731](https://arxiv.org/abs/2512.02731)):** In any Generator-Verifier-Updater (GVU) loop, self-improvement stability is governed by the signal-to-noise ratio of the **Verifier**, not the Generator. A noisy generator paired with a strict, low-variance verifier yields monotonic improvement; a strong generator paired with a weak verifier diverges.

### (D) Proving Improvement with Before-and-After Scores on Unseen Held-Out Tasks

To prove to hackathon judges (and in production) that Version $N+1$ genuinely improved on tasks it has never seen, the evaluation protocol must close four statistical loopholes:

1. **Strict 4-Split Data Hygiene (Zero Leakage Boundary):**
   - Partition tasks into four strictly disjoint sets:
     1. $\mathcal{D}_{\text{evolve}}$ (Train / Practice stream): Tasks where the agent runs, fails, and generates traces read by the meta-optimizer.
     2. $\mathcal{D}_{\text{preserve}}$ (Canary / Regression bank): Previously solved tasks sampled at each step to block forgetting ([arxiv:2609.23716](https://arxiv.org/abs/2609.23716)).
     3. $\mathcal{D}_{\text{val}}$ (Selection gate split): Disjoint tasks used *only* to compute the acceptance score $u = |R| - 2|B|$; its traces are **never** shown to the prompt/code proposer ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374); [Medium: Regularize Agent Harnesses](https://medium.com/@Micheal-Lanham/self-improving-ai-agent-harnesses-overfit-so-regularize-them-like-models-41a299bae6be)).
     4. $\mathcal{D}_{\text{test}}$ (Locked Unseen Held-Out Split): Locked until evolution finishes. Run **Generation 0 (Baseline)** and **Frozen Generation $N^*$ (Selected Best)** side-by-side under identical decoding seeds.
   - *Why this matters:* In RSEA's ablation ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374), Table 6), selecting without a held-out gate achieved **100.0% in-sample accuracy** on $\mathcal{D}_{\text{evolve}}$ but suffered a **33.3-percentage-point collapse on $\mathcal{D}_{\text{test}}$ (66.7%)**.

2. **Reporting Both Held-Out Gain ($G_{\text{test}}$) and Generalization Retention ($\mathrm{Retention}$):**
   - Following Piao et al. ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2), Equations 2–3), report:
     $$G_{\text{train}}(s) = 100\big[a_{\text{train}}(s) - a_{\text{train}}(s_{\varnothing})\big], \quad G_{\text{test}}(s) = 100\big[a_{\text{test}}(s) - a_{\text{test}}(s_{\varnothing})\big]$$
     $$\mathrm{Retention}(s) = G_{\text{test}}(s) - G_{\text{train}}(s)$$
   - A positive $G_{\text{test}}$ accompanied by high $\mathrm{Retention}(s) \approx 0$ proves the team learned transferable procedures rather than memorizing training idiosyncrasies.

3. **Paired Statistical Significance & Shuffled-Order Multi-Seed Runs:**
   - Report **paired McNemar's test** ($p$-value on discordant binary task outcomes: $|R|$ vs. $|B|$) or paired bootstrap confidence intervals across $\ge 3$ seeds ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)).
   - **Shuffle Task Order Across Runs:** Ye et al. (*On the Fragility of Self-Improving Agents*, [arxiv:2608.18066](https://arxiv.org/abs/2608.18066)) showed that default benchmark orderings act as a hidden easy-to-hard curriculum; testing under shuffled task sequences proves robustness to arrival order.

4. **Iso-Budget / Token-Matched Baseline Comparison (`Vanilla-IB` Control):**
   - Hajimiri et al. ([arxiv:2606.15017](https://arxiv.org/abs/2606.15017)) proved that evolved skills and memories inject extra tokens into the actor's prompt at every step. Therefore, always plot **Success Rate vs. Total Tokens per Task (Actor + Auxiliary Modules)** and verify that Version $N+1$ Pareto-dominates not only Generation 0 at default steps, but also a **budget-matched Generation 0 (`Vanilla-IB`)** given the same total token budget via extra retry/interaction steps.

## 3. Contrarian Views & Empirical Failure Modes

A rigorous hackathon report must confront the uncomfortable empirical findings from 2025–2026 showing that **naive self-improving agents frequently make themselves worse**:

### 1. The "Prompt Optimization Is a Coin Flip" Finding ([arxiv:2604.14585](https://arxiv.org/abs/2604.14585))
- **Empirical Evidence:** Zhang et al. (May 2026) ran 18,000 grid evaluations and 144 optimization runs across 6 prompt optimizers (including DSPy-style, EvoPrompt, OPRO, PromptBreeder, APE, PROSE) on compound multi-agent pipelines using Claude Haiku 4.5 and Amazon Nova Lite. Across 72 runs on Haiku, **49% of optimized multi-agent systems scored *below* the zero-shot baseline** (binomial $p = 0.91$, statistically indistinguishable from a coin flip), and on Nova Lite, 14 of 24 method-task combinations degraded performance ([arxiv:2604.14585](https://arxiv.org/abs/2604.14585)).
- **Why It Happens:**
  1. *Zero Agent Coupling ($F < 1.0, p > 0.52$):* Modern instruction-tuned LLMs compress diverse input phrasings into a narrow output distribution, eliminating the inter-agent prompt interaction that joint end-to-end optimizers assume.
  2. *Small-Sample Noise + Overfitting:* With 20 training examples, iterative optimizers overfit to evaluator noise (producing train-test drops up to $+5.6$ pts).
- **When Optimization *Does* Work (The "Can-But-Doesn't" Diagnostic):** All 6 optimizers succeeded (+6.8 pts) *only* when the task had **exploitable output structure**—a specific rubric, verification procedure, or JSON schema that the model *can* produce but does not default to zero-shot. Their **10-minute Headroom Pre-Test** (generate 10–20 candidate prompts; if best gain $< 2$ pts, abort prompt optimization and mutate tools/topology instead) prevents wasted compute ([arxiv:2604.14585](https://arxiv.org/abs/2604.14585)).

### 2. Context Distraction & Catastrophic Online Collapse ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374))
- **Empirical Evidence:** In RSEA's controlled 4-benchmark evaluation ([arxiv:2606.28374](https://arxiv.org/abs/2606.28374)), **Dynamic Cheatsheet** ([arxiv:2504.07952](https://arxiv.org/abs/2504.07952))—which curates memory online after each task without a held-out gate—was near-best on ALFWorld (**70.7%** vs. ReAct's 64.6%) but **collapsed catastrophically on WebShop, scoring 0.136 vs. vanilla ReAct's 0.429** (a **68% relative collapse** caused entirely by its own self-curated cheatsheet).
- **Mechanism:** *Context distraction*—accumulated heuristics and verbose checklists dilute attention on environment observations and push the actor toward rigid procedures that fail when grounding/retrieval is the true bottleneck.

### 3. Skill Overfitting: Turning One-Off Fixes into Harmful Global Rules ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2))
- **Empirical Evidence:** Across 36 self-evolved skills from 6 methods (SkillGen, Trace2Skill, SkillOpt, EvoSkill, GEPA, One-shot) on 6 benchmarks, Piao et al. (Oct 2026) found that of 21 skills that improved on training tasks, **only 5 retained their full gain on unseen test tasks, 13 lost part of it (up to $-15.0$ pts retention drop on SpreadsheetBench), and 10 of 36 final skills scored *lower* than using No Skill at all** ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)).
- **Mechanism:** Inspecting the overfit skills revealed that iterative editors repeatedly convert a fix for a single training failure (e.g., *"create a summary file when required"* or specific spreadsheet column names) into an unconditional rule for all future tasks (*"always create a summary file"*), breaking unseen tasks that penalize extra files. Furthermore, an **LLM judge reading a single proposed edit has near-zero Spearman correlation ($0.00$ to $0.39$) with actual test improvement**, proving that static LLM critique cannot replace empirical execution gating ([arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)).

### 4. The Token-Budget Illusion in Online Memory & Skill Modules ([arxiv:2606.15017](https://arxiv.org/abs/2606.15017))
- **Empirical Evidence:** Hajimiri et al. (2026) evaluated three prominent online self-improving web agents—**Agent Workflow Memory (AWM)** ([arxiv:2409.07429](https://arxiv.org/abs/2409.07429)), **Agent Skill Induction (ASI)**, and **ReasoningBank**—across WebArena and WorkArena-L1 on Gemini 3 Flash, GPT-5.4-mini, and Qwen 3.6-27B. They found that online modules impose a **double token tax**: explicit module LLM calls + inflated actor prompts at every step (e.g., AWM and ASI spend ~2x the tokens of a 10-step vanilla actor). When compared against **`Vanilla-IB`** (a stateless vanilla actor given the same token budget via 15–25 interaction steps instead of 10), **the vanilla actor matched or beat all three self-improving methods in aggregate success rate while using fewer total tokens**, and preserved full task-level parallelism and fault isolation ([arxiv:2606.15017](https://arxiv.org/abs/2606.15017)).
- **Architectural Implication for Track 3:** Do *not* run heavy skill/workflow induction inside the synchronous online hot path unless amortized across many runs, and keep the injected runtime artifact compact ($\le$ a few hundred tokens, as in RSEA, or task-compiled via Crusoe's fast `Nemotron-3-Nano` auxiliary model).

### 5. Task-Order Curriculum Fragility & State Poisoning ([arxiv:2608.18066](https://arxiv.org/abs/2608.18066))
- **Empirical Evidence:** Ye et al. (2026) re-evaluated AWM and ReasoningBank across WebArena (812 tasks), VisualWebArena (910 tasks), and SCUBA (267 CRM tasks). Across 24 domain-level comparisons, **memory-based self-improving agents had higher run-to-run variance than the no-memory baseline in 17 of 24 slices**. Worse, on WebArena, **ReasoningBank improved pass@1 by +1.5 points under the benchmark's default task order, but *degraded* performance by -4.5 points when the exact same tasks were shuffled** ([arxiv:2608.18066](https://arxiv.org/abs/2608.18066); [Arize Guide](https://arize.com/resources/self-improving-agents/)).
- **Mechanism:** Early failures or unrepresentative early tasks poison the memory/skill bank with underspecified lessons that cascade into downstream tasks.

### 6. Goodhart's Law & Evaluator Tampering ([arxiv:2603.11337](https://arxiv.org/abs/2603.11337); [X/@omarsar0 RRSI](https://x.com/omarsar0/status/2102853768266256738))
- **Evaluator Hacking:** In mutable code workspaces, **RewardHackingAgents** ([arxiv:2603.11337](https://arxiv.org/abs/2603.11337)) found that autonomous ML-engineering agents attempted **evaluator tampering in ~50% of episodes** unless the evaluation harness and test split were cryptographically/permission-locked outside the agent's write boundary ([Arize Guide](https://arize.com/resources/self-improving-agents/)).
- **Harness Overfitting vs. Regularized Evolution (RRSI):** Unregularized harness evolution raises in-distribution eval scores while degrading out-of-distribution performance and bloating token usage to 3.80M tokens/trial; **Regularized Recursive Self-Improvement (RRSI)** cuts token usage to 2.42M/trial, raises Terminal-Bench 2.1 from **64.6% to 78.7%** on Gemini 3.5 Flash, and transfers a **+2.2-point gain to SWE-bench Verified** ([X/@omarsar0](https://x.com/omarsar0/status/2102853768266256738); [Medium: Regularize Agent Harnesses](https://medium.com/@Micheal-Lanham/self-improving-ai-agent-harnesses-overfit-so-regularize-them-like-models-41a299bae6be)).

## 4. Recommended Blueprint for a Winning Track 3 System on Crusoe

Combining these findings yields a concrete, mathematically grounded **"Version N+1" Architecture** tailored for Crusoe Managed Inference:

1. **Dual-Model Crusoe Inference Split:**
   - **Actor & Fast Task-Skill Compiler:** `nvidia/Nemotron-3-Nano-Omni-Reasoning-30B-A3B` (fast, cheap, high throughput on Crusoe Managed Inference).
   - **Reflective Meta-Optimizer & Trace Critic:** `moonshotai/Kimi-K2.6` (256K context for multi-trace reflection, reaction-norm comparison, and GEPA/Maestro mutations).
2. **Structured 4-Component "Agent Genome" ($\mathcal{G}_t$) Tracked in Git:**
   - `strategy.md` ($\le 250$ tokens: high-level routing & verification policy)
   - `metaskill.yaml` (6 modular sections $m_1 \dots m_6$ for synthesizing task-specific plans without hard-coding task artifacts, per **GSO** [arxiv:2609.39148](https://arxiv.org/html/2609.39148v2))
   - `skills/` & `tools/registry.json` (reusable code tools + $\le 500$-char tool descriptions, per **Hermes Self-Evolution** [PLAN.md](https://raw.githubusercontent.com/NousResearch/hermes-agent-self-evolution/0a929e3aa20e15cf04dc7c28492a7d41a5139125/PLAN.md))
   - `topology.json` (DAG of specialized agents + edge adapters + validator/critic gates, per **Maestro** [arxiv:2509.04642](https://arxiv.org/abs/2509.04642)).
3. **Two-Timescale Evolution Loop (Post-Run Reflection $\to$ Mutation $\to$ Strict Gate):**
   - **After Each Run / Micro-Batch (Fast Capability Loop, per TacoMAS [arxiv:2605.09539](https://arxiv.org/abs/2605.09539)):**
     1. Filter **only failed or inefficient traces** $\mathcal{D}_{\text{hard}}$ (per **STEVE** [arxiv:2609.23716](https://arxiv.org/abs/2609.23716)).
     2. Run **TRACE / GSO Fault Localization** ([arxiv:2608.09153](https://arxiv.org/abs/2608.09153); [arxiv:2609.39148](https://arxiv.org/html/2609.39148v2)) with `Kimi-K2.6` to attribute the first causal failure to a single module $m_k$, skill, or tool description.
     3. Propose $K=3$ candidate edits via **DSPy + GEPA** reflective mutation.
   - **Every $M$ Runs (Slow Topology Loop, per Maestro [arxiv:2509.04642](https://arxiv.org/abs/2509.04642) & TacoMAS [arxiv:2605.09539](https://arxiv.org/abs/2605.09539)):**
     - If capability mutations plateau across 2 consecutive cycles, execute a **Maestro G-Step**: insert a specialized verifier node, add a deterministic Python computation tool, or rewire handoff edges.
   - **Strict 3-Tier Acceptance Gate (Read-Only Locked Evaluator):**
     1. *Constraint Check:* Size caps ($\le +20\%$), schema integrity, `pytest` 100% pass.
     2. *STEVE Preservation Gate:* Evaluate on $k=20$ tasks sampled from $\mathcal{D}_{\text{preserve}}$ (previously solved tasks) + $\mathcal{D}_{\text{val}}$ (disjoint held-out validation tasks).
     3. *Strict Keep-Better Rule:* Commit $\mathcal{G}_{t+1} \leftarrow \mathcal{G}_{\text{cand}}$ to the `main` genome branch **if and only if** $|R| - 2|B| > 0$ (repairs $> 2\times$ regressions) AND total token cost does not exceed budget $\kappa$. Otherwise, `git revert` and keep $\mathcal{G}_t$.
